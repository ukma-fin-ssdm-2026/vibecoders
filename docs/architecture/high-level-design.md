# High level design

## 1. Архітектурний стиль
Для розробки "Організатора НРІ" обрано **клієнт-серверний стиль з монолітним бекендом**. Ми застосовуємо серверний рендеринг (SSR) з використанням FastAPI, Jinja2 та HTMX. Дані зберігаються в єдиній реляційній базі даних MySQL. Детальне обґрунтування цього рішення та відхилені альтернативи зафіксовані у `decisions/ADR-001-monolithic-backend.md`.

## 2. Основні компоненти
- **Web Client:** Інтерфейс користувача (браузер). Використовує HTMX для відправки запитів і заміни частин DOM-дерева.
- **Cloud Infrastructure & Reverse Proxy (Nginx):** Забезпечує маршрутизацію трафіку та гарантує доступність системи на рівні 99% (REL-003).
- **Backend (FastAPI Monolith):**
  - *Auth Controller:* Точка входу. Перевіряє сесії та маршрутизує запит.
  - *Security & Hashing Module:* Відповідає за безпечне криптографічне хешування паролів (SEC-001) та перевірку лімітів спроб авторизації (SEC-003).
  - *Configuration Manager:* Модуль для зчитування налаштувань, який дозволяє змінювати конфігурацію кімнат без перекомпіляції коду (MAINT-001).
  - *Game Management Service:* Керує ігровими сесіями (ліміти учасників, запис).
  - *Room Booking Service:* Перевіряє зайнятість кімнат.
  - *Notification Service:* Відповідає за формування системних сповіщень (наприклад, при скасуванні гри, FR-011).
- **Relational DB (MySQL):** Сховище даних користувачів (включно з хешами паролів та лічильником невдалих входів для SEC-003), ігрових сесій та розкладу. 
- **External SMTP Server:** Зовнішній сервіс для фактичної відправки електронних листів користувачам.

## 3. Інтерфейси взаємодії
- **Client ↔ Cloud Proxy:** Взаємодія через HTTP/HTTPS. Клієнт відправляє AJAX-запити, проксі-сервер перенаправляє їх на бекенд.
- **Backend ↔ Database:** Взаємодія через SQL-запити (ORM). Забезпечує ACID-транзакції для модулів Game та Room Services.
- **Game Service ↔ Notification Service:** Внутрішній виклик функцій у межах моноліту для ініціації процесу сповіщення.
- **Notification Service ↔ SMTP Server:** Взаємодія через протокол SMTP для передачі сформованого листа на пошту клієнта.
