# High-Level Design

## 1. Архітектурний стиль
Для розробки Організатора настільних рольових ігор обрано **багатошарову клієнт-серверну архітектуру (Monolithic API)**. Система розділена на відокремлений клієнтський застосунок та єдиний серверний бекенд, що взаємодіє з реляційною базою даних. Цей стиль забезпечує швидкість розробки, цілісність даних (ACID транзакції для запобігання овербукінгу кімнат) та простоту розгортання для невеликої команди.

## 2. Основні компоненти
- **Web Client:** Забезпечує інтерфейс користувача для Гравців, Майстрів та Адміністраторів. Відображає розклад, форми бронювання та списки ігор.
- **API Gateway / Auth Controller:** Точка входу для всіх запитів. Відповідає за перевірку JWT-токенів, ідентифікацію ролей (Майстер/Гравець) та маршрутизацію.
- **Game Management Service:** Модуль бізнес-логіки, що відповідає за створення ігрових сесій, контроль лімітів гравців та запис на гру.
- **Room Booking Service:** Модуль бізнес-логіки, який працює з календарем та перевіряє доступність кімнат, блокуючи подвійні бронювання.
- **Relational Database:** Сховище даних (користувачі, ігри, бронювання).

## 3. Інтерфейси взаємодії
- **Клієнт ↔ Сервер:** Взаємодія відбувається через **REST API**. Клієнт відправляє HTTP-запити (GET, POST, PUT, DELETE) у форматі JSON.
- **Сервер ↔ База даних:** Взаємодія через **SQL / ORM**. Сервіси звертаються до БД для виконання CRUD-операцій у межах безпечних транзакцій.
