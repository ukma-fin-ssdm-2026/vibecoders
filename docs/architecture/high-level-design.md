# High-Level Design

## 1. Архітектурний стиль
Для розробки Організатора настільних рольових ігор обрано **монолітну серверну архітектуру з використанням серверного рендерингу та гіпермедіа**. Система базується на фреймворку FastAPI, який генерує HTML-сторінки через шаблонізатор Jinja2, а динамічність інтерфейсу забезпечується бібліотекою HTMX без написання об'ємного клієнтського JavaScript. Цей стиль мінімізує час розробки для команди та забезпечує цілісність даних (ACID транзакції у MySQL для запобігання овербукінгу кімнат).

## 2. Основні компоненти
- **Web Client (Jinja2 + HTMX):** Клієнтська частина, що рендериться на сервері. HTMX відповідає за динамічне оновлення фрагментів сторінки (наприклад, статусу слотів у календарі) через AJAX-запити.
- **FastAPI Router / Auth Controller:** Точка входу для запитів. Перевіряє сесії користувачів, визначає ролі (Майстер/Гравець/Адмін) та маршрутизує запити до відповідних сервісів.
- **Game Management Service:** Модуль бізнес-логіки для керування іграми (створення, редагування, запис гравців, контроль лімітів).
- **Room Booking Service:** Модуль бізнес-логіки для перевірки доступності кімнат та блокування подвійних бронювань у календарі.
- **Relational Database (MySQL):** Сховище даних користувачів, ігрових сесій та графіку кімнат.

## 3. Інтерфейси взаємодії
- **Клієнт ↔ Сервер:** HTTP-запити. Замість чистого JSON, сервер віддає готові HTML-фрагменти (Jinja2), які HTMX безшовно вбудовує в DOM браузера.
- **Сервер ↔ База даних:** SQL-запити через ORM. Усі операції з бронювання кімнат виконуються в межах ізольованих транзакцій MySQL.
