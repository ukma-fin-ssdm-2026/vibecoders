## Сценарії атрибутів якості

### QAS-01: Надійність при конкурентному бронюванні (REL-001)

| Елемент | Опис |
|---|---|
| **Джерело стимулу** | 20 різних гравців/майстрів одночасно |
| **Стимул** | Намагаються забронювати один і той самий часовий слот однієї кімнати |
| **Середовище** | Нормальна робота системи, пікове навантаження |
| **Артефакт** | Room Booking Service + Relational Database |
| **Реакція** | Лише один запит отримує підтвердження бронювання; усі інші відхиляються з коректним повідомленням про помилку (409 Conflict) |
| **Міра реакції** | 0 випадків подвійного бронювання з 20 одночасних спроб; час обробки конфлікту < 500мс |

### QAS-02: Продуктивність оновлення лічильника місць (PERF-001)

| Елемент | Опис |
|---|---|
| **Джерело стимулу** | Гравець |
| **Стимул** | Натискає "Записатися" на грі з вільними місцями |
| **Середовище** | Нормальна робота системи |
| **Артефакт** | Web Client (HTMX) + Game Management Service |
| **Реакція** | Лічильник вільних місць оновлюється на клієнті без повного перезавантаження сторінки |
| **Міра реакції** | Оновлення відображається не пізніше ніж через 1 секунду після успішного запису на сервері |

### QAS-03: Доступність системи (REL-003)

| Елемент | Опис |
|---|---|
| **Джерело стимулу** | Збій бекенд-процесу (наприклад, необроблений виняток, вихід з ладу) |
| **Стимул** | Процес FastAPI аварійно завершується |
| **Середовище** | Робочий час клубу (нормальна експлуатація) |
| **Артефакт** | Cloud Infrastructure & Reverse Proxy |
| **Реакція** | Менеджер процесів (systemd) на веб-сервері виявляє аварійне завершення процесу FastAPI і автоматично перезапускає його; Nginx на цей час повертає 502/503 |
| **Міра реакції** | Сукупний простій не перевищує ≈3,6 години на місяць (99% доступності) |

## Зв'язок із Threat Model

Детальний аналіз STRIDE-ризиків та контрзаходів для вимог, пов'язаних
із безпекою та цілісністю даних (SEC-002, REL-001, REL-002), наведено
в `threat-model.md`. Зокрема:
- **Tampering** (TB1) підтверджує серверну валідацію бронювання кімнат — узгоджено з REL-001.
- **Information Disclosure** (TB2) підтверджує фільтрацію чутливих полів через Pydantic — узгоджено з SEC-002.
- **Elevation of Privilege** (TB1) підтверджує RBAC-перевірки в Auth Controller — узгоджено з FR-008, FR-002.
- **Denial of Service** (TB1) частково торкається REL-003.
