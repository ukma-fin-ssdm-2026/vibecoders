# ADR: Міграція сховища даних на SQLite за допомогою SQLAlchemy

## Контекст
Початкова версія системи використовувала словники в пам'яті (`store.py`) для зберігання даних. Це рішення було достатнім для прототипування, але не підходило для реального використання через втрату даних при перезапуску сервера та проблеми з багатопотоковістю (race conditions). 

## Рішення
Ми перевели систему на використання SQLite за допомогою ORM SQLAlchemy.
- Для забезпечення зворотної сумісності з існуючими роутами та мінімізації змін у бізнес-логіці ми імплементували проксі-класи (`DBProxyDict`, `EnrollmentsProxy`).
- Дані тепер персистентно зберігаються у файлі `club.db`.
- Проблему перегонів даних (REL-001, REL-002) вирішено додаванням `threading.RLock()` на рівні доступу до бази, що забезпечує атомарність перевірок та запису.

## Наслідки
**Позитивні:**
- Дані надійно зберігаються між перезапусками програми.
- Вирішено проблеми конкурентного доступу до бронювання кімнат.
- Збережено всі 248+ оригінальних тестів без необхідності переписувати роути.
- Закладено міцний фундамент для майбутньої міграції на PostgreSQL.

**Негативні:**
- Дещо зросла внутрішня складність модуля `store.py` через проксі-класи.
