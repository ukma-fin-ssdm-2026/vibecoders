# Моделювання загроз (STRIDE)

## Межі довіри (Trust Boundaries)
На основі нашої діаграми розгортання виділено дві ключові межі довіри:
1. **TB1 (Інтернет ↔ FastAPI Server):** Межа між браузером клієнта (HTMX) та нашим веб-сервером. Найвищий ризик атак ззовні.
2. **TB2 (FastAPI Server ↔ MySQL Database):** Межа між бекендом та сховищем даних у внутрішній мережі.
3. **TB3 (FastAPI Server ↔ External SMTP):** Межа між нашим бекендом та зовнішнім поштовим сервісом для надсилання сповіщень.

## Аналіз ризиків за STRIDE

| Категорія (STRIDE) | Компонент / Межа | Опис сценарію | Оцінка | Контрзахід / Рішення |
| :--- | :--- | :--- | :--- | :--- |
| **Spoofing** (Підміна особи) | TB1 (Інтернет ↔ FastAPI) | Зловмисник може спробувати підробити сесійні cookie, щоб видати себе за "Власника клубу" і видаляти чужі ігри. | Висока | Використання криптографічно підписаних сесій у FastAPI із прапорцями `HttpOnly` та `Secure` для cookie. |
| **Tampering** (Втручання) | TB1 (Інтернет ↔ FastAPI) | Гравець перехоплює HTMX POST-запит на бронювання і змінює `room_id` на ID кімнати, яка вже зайнята, намагаючись викликати подвійне бронювання. | Висока | **Room Booking Service** на бекенді повинен суворо валідувати доступність кімнати перед транзакцією в БД, ігноруючи клієнтські перевірки. |
| **Repudiation** (Невідмовність) | FastAPI Server | Майстер скасовує гру, але потім заперечує це, скаржачись власнику клубу на помилку системи. | Середня | Додати логування критичних дій (створення/видалення ігор) з прив'язкою до ID користувача та міткою часу. |
| **Information Disclosure** (Розголошення) | TB2 (FastAPI ↔ MySQL) | Через помилку розробника, API-ендпоінт, що повертає список учасників гри для рендеру Jinja2, може випадково включити поле `password_hash` або `contacts` з БД. | Висока | Використання Pydantic-схем (response models) у FastAPI для жорсткої фільтрації чутливих полів перед відправкою даних на клієнт. |
| **Elevation of Privilege** (Підвищення привілеїв) | TB1 (Інтернет ↔ FastAPI) | Звичайний гравець вручну надсилає HTTP DELETE запит на ендпоінт `/games/{id}`, який не прихований у його інтерфейсі HTMX, але доступний на сервері. | Висока | **Auth Controller** повинен перевіряти Role-Based Access Control (RBAC) на кожному маршруті: відхиляти запит зі статусом `403 Forbidden`, якщо роль не Master або Admin. |
| **Denial of Service** (Відмова) | TB1 (Інтернет ↔ FastAPI) | Зловмисник (або бот) масово надсилає запити на оновлення календаря, вичерпуючи пул з'єднань бази даних MySQL. | Середня | Впровадження Rate Limiting (обмеження частоти запитів) на рівні FastAPI Router для IP-адрес. Наразі ризик **свідомо частково прийнятий** до етапу релізу. |
| **Information Disclosure** (Розголошення) | TB3 (FastAPI ↔ SMTP) | Перехоплення незашифрованого трафіку між сервером та зовнішнім SMTP-сервісом дозволяє зловмиснику прочитати вміст листів-сповіщень. | Середня | Використання виключно зашифрованого з'єднання (TLS/SSL) для підключення до поштового сервера на рівні конфігурації `SMTP_TLS=True`. |
