# Моделювання загроз (STRIDE)

## Межі довіри (Trust Boundaries)
На основі нашої діаграми розгортання виділено дві ключові межі довіри:
1. **TB1 (Інтернет ↔ FastAPI Server):** Межа між браузером клієнта (HTMX) та нашим веб-сервером. Найвищий ризик атак ззовні.
2. **TB2 (FastAPI Server ↔ SQLite Database):** Межа між бекендом та сховищем даних у внутрішній мережі.
3. **TB3 (FastAPI Server ↔ External SMTP):** Межа між нашим бекендом та зовнішнім поштовим сервісом для надсилання сповіщень.

## Аналіз ризиків за STRIDE

| Категорія (STRIDE) | Компонент / Межа | Опис сценарію | Оцінка | Контрзахід / Рішення |
| :--- | :--- | :--- | :--- | :--- |
| **Spoofing** (Підміна особи) | TB1 (Інтернет ↔ FastAPI) | Зловмисник може спробувати підробити сесію, щоб видати себе за "Власника клубу" і видаляти чужі ігри. | Висока | Використання Bearer-токенів замість cookie. Токени зберігаються в SQLite і передаються в заголовку `Authorization`. |
| **Tampering** (Втручання) | TB1 (Інтернет ↔ FastAPI) | Гравець перехоплює POST-запит на бронювання і змінює `room_id` на ID кімнати, яка вже зайнята, намагаючись викликати подвійне бронювання. | Висока | **Room Booking Service** на бекенді суворо валідує доступність кімнати перед транзакцією в БД (з увімкненими `PRAGMA foreign_keys=ON`), ігноруючи клієнтські перевірки. |
| **Repudiation** (Невідмовність) | FastAPI Server | Майстер скасовує гру, але потім заперечує це. | Середня | Додати логування критичних дій (створення/видалення ігор) з прив'язкою до ID користувача та міткою часу. |
| **Information Disclosure** (Розголошення) | TB2 (FastAPI ↔ SQLite) | Через помилку розробника, API-ендпоінт може випадково включити поле `password_hash` або `contacts` з БД. | Висока | Використання Pydantic-схем (response models) у FastAPI для жорсткої фільтрації чутливих полів перед відправкою. |
| **Elevation of Privilege** (Підвищення привілеїв) | TB1 (Інтернет ↔ FastAPI) | Звичайний гравець вручну надсилає HTTP DELETE запит на ендпоінт `/games/{id}`. | Висока | **Auth Controller** перевіряє Role-Based Access Control (RBAC) на кожному маршруті: відхиляє запит зі статусом `403 Forbidden`, якщо роль не Master або Admin. |
| **Denial of Service** (Відмова) | TB1 (Інтернет ↔ FastAPI) | Зловмисник масово надсилає запити на оновлення календаря, вичерпуючи ресурси. | Середня | Впровадження Rate Limiting (обмеження частоти запитів). Наразі ризик **свідомо частково прийнятий** до етапу релізу. |
| **Information Disclosure** (Розголошення) | TB3 (FastAPI ↔ SMTP) | Перехоплення незашифрованого трафіку між сервером та зовнішнім SMTP дозволяє зловмиснику прочитати вміст листів. | Середня | Використання виключно зашифрованого з'єднання (TLS/SSL) для підключення до поштового сервера. |

## Використання ШІ
- Цей документ оновлено з допомогою ШІ для відображення переходу з cookie на Bearer-токени та міграції на базу даних SQLite.
