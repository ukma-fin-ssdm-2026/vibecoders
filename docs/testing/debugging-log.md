## Запис 1. `time_overlap`: нестроге порівняння на межі інтервалу (`<=` замість `<`)

| Поле | Значення |
|---|---|
| Де | `src/api/store.py`, функція `time_overlap(start_a, minutes_a, start_b, minutes_b)` |
| Хто використовує | `find_busy_game` (зайнятість кімнати й майстра: FR-006, REL-002) і `next_free_start` (пошук найближчого вільного слота) |
| Вимоги | US-002, REL-002 |
| Статус | виправлено, регресійні тести в CI |

### Симптом

Гра, що починається рівно в момент закінчення іншої гри в тій самій кімнаті (наприклад, одна триває 18:00-20:00, нова починається о 20:00), вважалася такою, що перетинається. Створення такої гри відхилялося з помилкою `ROOM_BUSY` (або `MASTER_BUSY`, якщо майстер той самий), хоча кімната й майстер вільні. Пошук найближчого вільного слота `next_free_start` у цьому випадку не завершувався: цикл `while` повертав кінець гри-перешкоди, а ця сама точка знову вважалася зайнятою.

### Причина

Інтервали гри мають вигляд `[початок, кінець)`: момент закінчення належить уже наступному слоту. Два таких інтервали перетинаються тоді й лише тоді, коли обидва порівняння **строгі**:

```
A.початок < B.кінець  і  B.початок < A.кінець
```

З нестрогим `<=` слоти, що торкаються лише межею, помилково вважалися перетином. Помилка ховалася, бо типові перевірки (повне збігання, часткове перетинання, слоти в різні дні) давали правильну відповідь. Ламався лише випадок «межа в межу».

### Виправлення

Обидва порівняння зробили строгими:

```python
def time_overlap(start_a: datetime, minutes_a: int, start_b: datetime, minutes_b: int) -> bool:
    return start_a < start_b + timedelta(minutes=minutes_b) and start_b < start_a + timedelta(minutes=minutes_a)
```

### Регресійні тести

Щоб переконатися, що тести справді ловлять цю помилку, в одноразовій копії репозиторію повернули `<=` і запустили їх. Результат:

### Висновок

1. Для напіввідкритих інтервалів `[початок, кінець)` потрібні строгі нерівності. Перед написанням перевірки варто записати, чи кінець інтервалу входить у нього.
2. Для логіки з інтервалами окремо перевіряємо межі: «межа в межу», однакові початки, перетин на одну хвилину. Прикладів «посередині» замало.
3. Властивість «слоти впритул ніколи не перетинаються» краще перевіряти property-тестом (Hypothesis): він знайшов контрприклад без підказки.
4. Функція, від якої залежить цикл «шукати, доки вільно», перетворює помилку на межі в нескінченний цикл. Тести таких циклів треба обмежувати за часом, щоб збій був помітним у CI, а не «підвішував» прогін.
