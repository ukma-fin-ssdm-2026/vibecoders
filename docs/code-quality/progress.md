## 1. Що реалізовано

Файли модуля `src/api`:

- `main.py`, `schemas.py`, `security.py`, `store.py`, `errors.py`, `spec.py`, `generate_openapi.py`, `requirements.txt`
- `routes/`: `auth.py`, `games.py`, `rooms.py`
- `notifications.py`: **новий компонент Лаб 5**, сповіщення гравців про скасування гри
- `tests/`: тести маршрутів, схем, безпеки, сховища, властивостей, таблиці рішень, продуктивності, сповіщень

**Новий компонент (`notifications.py`, FR-011):** при видаленні гри (`DELETE /api/v1/games/{id}`) функція `notify_game_cancelled` створює по одному сповіщенню для кожного записаного гравця. Сповіщення зберігаються в пам'яті (як і решта прототипу), перевірені тестами `test_notifications.py`: сповіщення отримують усі записані гравці, гра без гравців нічого не створює, заборонене видалення (403) нікого не сповіщає. Відправку листа через SMTP (Notification Service з `high-level-design.md`) і сховище сповіщень у БД додамо на наступних етапах.

## 2. Як запустити тести

З кореня репозиторію:

    python -m pytest

Конфігурація тестів лежить у `pytest.ini` (шлях до тестів: `src/api/tests`). Змінна середовища `PYTHONPATH` не потрібна.

Останній запуск: Python 3.9, pytest 8, усі тести пройдено, покриття 99 % (поріг у CI 95 %). Нові тести: `test_notifications.py` (5 тестів компонента) і `test_quality_goals.py` (числові межі з `quality-attributes.md`).

## 4. Відгук від іншої команди (Team 3)

Звіт про наш код отримано. 

| Зауваження рецензентів | Рішення команди | 
| --- | --- | 
| Логувати спроби входу й додати тимчасове блокування після невдалих спроб | Блокування після 5 невдалих спроб реалізовано (SEC-003); логування спроб входу відкладено | 
| Додати `correlation_id` для трасування запитів | Відкладено до подальшого розвитку системи | 
| Додати чітку транзакційну межу між пов'язаними операціями | Відкладено до підключення БД |
| race condition при PATCH | Не застосовується до поточного прототипу | 

Сильні сторони, які відзначили рецензенти: розділення автентифікації й авторизації в `security.py` (`get_current_user`, `require_roles`), чітка структура роутів і схем, централізована обробка помилок без витоку деталей.

## 5. Відомі обмеження

- Тести не покривають рольову перевірку (`require_roles`), PATCH-ендпоінти, кімнати (`rooms.py`) і відповіді 401/403.
- У `store.py` є захардкоджені `PASSWORD_SALT` і демонстраційні токени.
- Немає обмеження кількості спроб входу (SEC-003).
