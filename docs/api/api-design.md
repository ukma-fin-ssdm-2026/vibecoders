# Проєктування API (API Design)

## 1. Модель ресурсів (REST)
API використовує іменники у множині для позначення ресурсів, оскільки дієслова в шляхах порушують RESTful-підхід.
- **`/api/v1/games`**: Керування ігровими сесіями.

## 2. Семантика HTTP методів та ідемпотентність
- `GET`: Безпечний та ідемпотентний метод для читання.
- `POST`: Неідемпотентний метод для створення ресурсів.
- `PUT`: Ідемпотентний метод для повної заміни ресурсу.
- `DELETE`: Видалення ресурсу.

## 3. Коди статусів та структура помилок
API суворо розділяє статуси замість того, щоб повертати `200 OK` з текстом помилки всередині тіла.
- `201 Created`: Використовується для успішних POST-запитів.
- `204 No Content`: Використовується після успішного видалення.
- `400 Bad Request`: Помилка валідації вхідних даних.
- `401 / 403`: Розділення помилок автентифікації та відсутності прав доступу.
- `404 Not Found`: Ресурс відсутній.
- `500 Internal Server Error`: Серверна помилка.
